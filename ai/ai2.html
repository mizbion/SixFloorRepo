📖 데이터의 정의 — 모든 것이 데이터다

우리 주변의 모든 것이 데이터입니다. 숫자뿐 아니라 텍스트·사진·음악·영상·위치 정보까지. 지금 이 순간에도 세계 어딘가에서 수천만 개의 데이터가 생성되고 있습니다.

빅데이터란 무엇인가?

02-1 · 빅데이터의 속성 5V와 개발자 관점

🔍 빅데이터 = 단순히 "많은 데이터"가 아니다

빅데이터란 다양한 형태를 갖고 있고, 생성 속도가 빠르면서, 가치를 창출할 수 있는 대량의 데이터를 의미합니다. 5가지 속성(5V)으로 정의됩니다.

V1

Volume
규모

페타바이트(PB)~제타바이트(ZB) 단위의 방대한 데이터 양

TB → PB → EB → ZB
V2

Variety
다양성

텍스트·이미지·영상·음성·센서 등 다양한 형태의 데이터

정형·반정형·비정형
V3

Velocity
속도

실시간으로 생성·처리·분석되어야 하는 빠른 데이터 흐름

실시간 스트리밍
V4

Veracity
진실성

신뢰할 수 있는 정확한 데이터. 불확실성과 노이즈를 관리

데이터 품질
V5

Value — 가치 ⭐ 가장 중요!

데이터를 분석해 실질적인 비즈니스 가치를 창출해야 합니다. 아무리 크고 빠른 데이터도 가치를 못 만들면 의미가 없습니다.

Why does it matter?ROI비즈니스 임팩트
🤔 데이터는 많을수록 좋을까? — 프로그래머의 관점
🚫 Garbage In, Garbage Out
AI 모델에 품질이 낮은 데이터를 넣으면 아무리 좋은 알고리즘을 써도 쓰레기 결과가 나옵니다. 데이터 저장 비용도 무시할 수 없습니다. AWS S3 1TB/월 ≈ $23, 의미 없는 데이터를 쌓으면 순수 손실입니다.

❌ 나쁜 데이터의 특징

결측값(NaN)이 많음
중복 데이터 다수 포함
편향된 샘플 (대표성 없음)
레이블 오류 (잘못 분류된 데이터)
노이즈·이상치(Outlier) 미처리

✅ 좋은 데이터의 특징

결측값 처리 완료
중복 제거 (deduplication)
다양한 계층·상황 대표
정확한 레이블링
정규화·스케일링 완료

📰 실제 편향 사례 — 개발자가 반드시 알아야 할 것들
이미지 데이터베이스를 분석한 결과, 남성은 '사무실·비즈니스'와 연결되고 여성은 '어린이·집'과 연결되어 있었습니다. 더 충격적인 것은 백인은 '도구'와, 흑인은 '무기'와 연결되어 있었다는 사실입니다.

이는 AI가 고의로 차별한 게 아니라, 인간 사회의 편향이 데이터에 그대로 녹아들었기 때문입니다. 이 AI를 채용 도구로 쓴다면? 대출 심사에 쓴다면? 경찰 범죄 예측에 쓴다면? 심각한 결과를 낳습니다.
피부암 진단 AI가 백인 피부 이미지로만 주로 학습되어 유색인종 피부에서 진단 정확도가 크게 낮아졌습니다. 피부암 조기 발견이 생사를 가를 수 있는 상황에서 이는 매우 심각한 문제입니다.

💻 개발자의 책임: 모델을 만들기 전에 훈련 데이터의 인구 통계적 분포를 반드시 확인해야 합니다. df['skin_tone'].value_counts(normalize=True)
아마존이 이력서 심사 AI를 개발했으나, 과거 10년간의 채용 데이터로 학습한 결과 여성 지원자를 체계적으로 낮게 평가하는 문제가 발견되었습니다. 기술직 채용에서 남성이 압도적으로 많았던 역사적 데이터가 편향을 만들어낸 것입니다.

결국 2018년 아마존은 이 시스템을 폐기했습니다. 역사적 편향(Historical Bias)의 대표적 사례입니다.
Google 포토 앱이 흑인 커플의 사진을 '고릴라'로 자동 태그 처리한 사건입니다. 훈련 데이터에 다양한 피부색의 인물 사진이 충분히 포함되지 않았기 때문입니다.

Google은 즉시 사과하고 수정했으나, 이 사건은 AI 편향이 단순한 기술 문제가 아닌 사회적·윤리적 문제임을 전 세계에 알렸습니다.
🔬 데이터 편향의 유형 — 개발자가 알아야 할 3가지

📝 레이블 편향
Labeling Bias

데이터를 분류·표시(레이블링)할 때 사람의 주관이 개입. "사나운 물고기" 실험처럼, 애매한 데이터는 사람마다 다르게 판단합니다.

해결: 다수 레이블러 합의

📜 역사적 편향
Historical Bias

과거의 사회적 불평등이 데이터에 그대로 반영. Amazon 채용 AI처럼 과거의 편향된 채용 패턴을 AI가 그대로 학습.

해결: 데이터 재균형화

📐 측정 편향
Measurement Bias

특정 그룹에서 데이터 수집 방식이 달라 생기는 편향. 의료 AI의 피부색 편향처럼 일부 그룹만 충분히 측정된 경우.

해결: 균형 잡힌 샘플링

02-2 · 데이터 수집 방법과 품질 기준

📋 좋은 데이터의 4가지 조건
1
대표성 (Representativeness)

머신러닝 학습 데이터는 현실 세계를 고르게 반영해야 합니다. 특정 집단·상황만 과도하게 포함되면 AI가 현실과 다른 편향된 판단을 내립니다.
예시 한국 사람 얼굴 인식 AI를 만든다면 → 다양한 연령대·성별·지역 사람들의 사진이 균등하게 포함되어야 합니다.

2
충분한 양 (Sufficient Volume)

데이터가 너무 적으면 모델이 훈련 데이터만 외우는 과적합(Overfitting)이 발생합니다. 일반적으로 클래스당 최소 수백~수천 개의 데이터가 필요합니다.
규칙 이미지 분류: 클래스당 ≥1,000장 / 텍스트 분류: 클래스당 ≥500개

3
품질 (Quality)

다른 데이터와 동떨어진 이상치(Outlier), 결측값(NaN), 중복 데이터는 모델 성능을 크게 저하시킵니다. 업계에서는 데이터 과학자가 시간의 70~80%를 데이터 정제에 씁니다.
도구 pandas.isna() / drop_duplicates() / IQR 이상치 제거

4
관련 있는 특성 (Relevant Features)

AI는 원본 데이터가 아닌 데이터에서 추출한 특성(Feature)으로 학습합니다. 무관한 특성이 많으면 모델이 혼란을 겪습니다. 특성 선택(Feature Selection)과 특성 엔지니어링(Feature Engineering)이 중요합니다.
예시 집값 예측: "이름" 컬럼은 삭제, "지하철역과의 거리" 특성은 직접 계산해서 추가

💻 개발자가 반드시 알아야 할 개인정보 보호 기술
비밀번호를 그대로 DB에 저장하면 해킹 시 모든 사용자 비밀번호가 노출됩니다. 반드시 해시 함수로 변환해 저장해야 합니다.
import bcrypt # 비밀번호 해시화 (저장 시) password = "myPassword123" hashed = bcrypt.hashpw(password.encode(), bcrypt.gensalt()) # DB에는 hashed만 저장 → 원본 비밀번호는 복원 불가! # 로그인 시 검증 print(bcrypt.checkpw("myPassword123".encode(), hashed)) # True print(bcrypt.checkpw("wrongPassword".encode(), hashed)) # False
분석에 사용할 데이터에서 개인을 식별할 수 있는 정보(이름, 주민번호, 전화번호)를 제거하거나 변환합니다.
import pandas as pd df = pd.read_csv("users.csv") # 1. 직접 식별자 제거 df.drop(columns=["name", "phone", "email"], inplace=True) # 2. 준식별자 일반화 (나이를 연령대로) df["age_group"] = pd.cut(df["age"], bins=[0,19,29,39,99], labels=["10대","20대","30대","40대+"]) df.drop(columns=["age"], inplace=True) # 3. 위치 정보 마스킹 (소수점 줄이기) df["lat"] = df["lat"].round(2) # ~1km 정밀도로 낮춤
한국의 개인정보 보호법(PIPA)은 개인정보를 수집·처리할 때 지켜야 할 원칙을 규정합니다. 위반 시 최대 5억원 과징금이 부과될 수 있습니다.

핵심 원칙: ① 최소 수집 — 꼭 필요한 정보만 수집 ② 명확한 동의 — 수집 목적을 명확히 알리고 동의 획득 ③ 안전한 보관 — 암호화·접근 통제 ④ 파기 의무 — 목적 달성 후 즉시 삭제
