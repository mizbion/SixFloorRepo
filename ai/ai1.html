01-2

인공지능의 역사

📚 배경지식 — 클릭해서 확인하기
영국 수학자·논리학자(1912~1954). 2차 세계대전 중 독일 암호 에니그마를 해독해 연합군 승리에 기여했습니다. 영화 이미테이션 게임(2014)이 그의 이야기를 담고 있습니다.

1936년 '튜링 머신' 개념을 제안, 현대 컴퓨터의 이론적 토대를 마련했습니다. 프로그래밍에서 배우는 알고리즘·연산 개념의 뿌리가 바로 여기서 시작됩니다.
사람이 텍스트 대화를 통해 상대가 사람인지 기계인지 구별하지 못하면, 그 기계를 "지능이 있다"고 판단하는 방법입니다.

• 2014년 챗봇 '유진 구스트만'이 최초로 통과했다고 발표 — 그러나 13세 우크라이나 소년 설정으로 오류를 가릴 수 있다는 비판을 받았습니다.
• 현재 GPT-4, Claude 등은 대부분의 상황에서 사람과 구별하기 어렵습니다.
AI에 대한 기대가 지나치게 높아진 뒤 성과가 나오지 않아 연구비와 관심이 급격히 줄어드는 시기입니다.

• 1차 겨울(1970~1980): 연산 능력·데이터 부족으로 자금 삭감
• 2차 겨울(1987~1997): 전문가 시스템 유지비 급증, 세계 경기 불황

💡 개발자 교훈: 기술의 과대 광고(Hype)를 경계하고, 지금의 AI 붐도 현명하게 바라봐야 합니다.
2012년 이미지넷 대회에서 AlexNet이 기존 방법 대비 오류율을 26% → 15%로 낮추며 딥러닝 시대를 열었습니다.

핵심 요인: ① GPU를 활용한 대규모 병렬 연산 ② 대용량 데이터셋(ImageNet) ③ ReLU·드롭아웃 등 새로운 학습 기법

이후 Google, Facebook, Amazon 등이 앞다퉈 딥러닝 연구에 투자하면서 현재의 AI 전성기가 시작되었습니다.
구글 딥마인드의 알파고가 세계 바둑 챔피언 이세돌을 4:1로 꺾었습니다.

알파고의 핵심 기술:
• 강화학습(Reinforcement Learning): 스스로 수백만 번 대국하며 최적의 수를 학습
• 몬테카를로 트리 탐색(MCTS): 경우의 수를 확률적으로 탐색
• 정책망 + 가치망: 딥 신경망 2개가 협력

💻 중요한 것: 알파고는 바둑 외에는 아무것도 못 합니다. 전형적인 약인공지능입니다.

생활 속의 인공지능 — 개발자 관점으로

🎯 1. 추천 시스템 — 알고리즘으로 이해하기

추천 시스템은 사용자 데이터를 분석해 맞춤 콘텐츠·상품을 제안하는 시스템입니다. 아마존 매출의 35%, 넷플릭스 시청의 80%가 추천 알고리즘에서 비롯됩니다. 프로그래머라면 이 시스템을 직접 설계하고 구현할 수 있어야 합니다.

📄 콘텐츠 기반 필터링

아이템의 속성(장르·키워드·태그)과 사용자 선호도를 매칭

아이템 분석벡터 유사도

예: 액션 영화를 좋아하면 → 다른 액션 영화 추천
장점: 다른 사용자 데이터 불필요
단점: 새로운 장르 탐색이 어려움

👥 협업 필터링

나와 비슷한 패턴의 다른 사용자 행동을 기반으로 추천

사용자 기반아이템 기반

예: "당신과 비슷한 사람들이 이것도 샀어요"
장점: 새로운 발견 가능
단점: 콜드 스타트 문제 발생

📐 협업 필터링 Python 구현 원리

# 사용자-아이템 평점 행렬 예시 ratings = { "철수": {"파이썬책": 5, "자바책": 3, "AI책": None}, "영희": {"파이썬책": 4, "자바책": 3, "AI책": 5}, "민준": {"파이썬책": 5, "자바책": 2, "AI책": 4}, } # 철수 ↔ 영희: 파이썬책(5,4) 자바책(3,3) → 취향 유사 # 철수 ↔ 민준: 파이썬책(5,5) 자바책(3,2) → 취향 유사 # → 영희, 민준 모두 AI책을 높게 평가 → 철수에게 AI책 추천! # 코사인 유사도(Cosine Similarity)로 사용자 간 유사성 측정
⚠️ 콜드 스타트(Cold Start): 신규 사용자나 신상품은 데이터가 없어 추천이 부정확합니다. 이를 해결하기 위해 인기 아이템 추천, 설문 기반 초기 선호도 수집 등의 기법을 사용합니다.
🫧 필터 버블(Filter Bubble): 알고리즘이 내가 좋아할 것만 보여줘 다양한 정보를 접하지 못하는 현상. 개발자는 다양성(Diversity)·우연성(Serendipity)을 의도적으로 설계해야 합니다.

💬 3. 챗봇 — 규칙 기반 vs AI 기반, 직접 비교

최초의 챗봇 일라이자(ELIZA, 1966)는 정신 치료사 역할로 만들어졌습니다. 지금은 고객 응대·학습 보조·코딩 도우미 등 다양한 분야에 쓰입니다. 프로그래머라면 직접 챗봇을 구현할 수 있어야 합니다.

🚗 4. 자율주행차 — 이동하는 소프트웨어 시스템

자율주행차는 단순한 "자동차"가 아닌 이동하는 컴퓨터 시스템입니다. 카메라·레이더·LiDAR 센서 데이터를 실시간으로 처리하는 수십만 줄의 코드가 작동합니다.

왜 AI와 친해져야 할까? — 프로그래머의 미래

🔮 AI 시대 개발자 일자리 — 대체? vs 진화?

"AI가 개발자를 대체할까?" 걱정하는 목소리가 있습니다. 하지만 데이터는 다른 방향을 가리킵니다. 미국 노동통계국(BLS)은 2022~2032년 소프트웨어 개발자 수요가 25% 증가할 것으로 전망했습니다.

❌ AI가 대체하는 개발 업무

단순 반복 코드 작성 (boilerplate)
정해진 패턴의 CRUD 구현
기계적인 코드 변환·마이그레이션
간단한 버그 수정 및 테스트 코드 생성

✅ AI가 강화하는 개발자 역량

복잡한 시스템 설계·아키텍처 결정
요구사항 분석 및 문제 정의
AI 결과물 비판적 검토·품질 관리
팀·고객과의 소통·협상

📊 MS 보고서 핵심 (AI를 위한 준비, 2019): 수요가 높은 일자리의 약 60%가 대인 커뮤니케이션·창의적 업무·전략적 의사 결정 직군. 단순 반복 업무는 줄고 인간 고유의 판단·공감·창의 업무는 늘어납니다.
한국고용정보원: 직종보다 종합적 분석·판단·의사소통 역량을 갖춘 사람이 AI 대체 위험이 낮습니다. AI는 인간을 보조하는 수단이 될 가능성이 높습니다.

🧠 AI가 대체 못하는 프로그래머의 강점 6가지

🎯 문제 정의 능력

AI는 주어진 문제를 잘 풀지만, "무엇이 진짜 문제인가?"를 정의하는 것은 인간만 할 수 있습니다. 요구사항 분석, 비즈니스 맥락 이해가 핵심.

🏗️ 시스템 아키텍처 설계

마이크로서비스, DB 설계, 확장성 고려 등 전체 시스템을 조망하는 설계 능력은 AI가 아직 취약합니다.

🔍 비판적 코드 리뷰

AI가 생성한 코드의 보안 취약점·성능 문제·유지보수성을 비판적으로 판단하는 능력. AI 시대에 더욱 중요.

💡 프롬프트 엔지니어링

AI에게 정확한 질문을 던지고, 원하는 결과를 이끌어내는 능력. AI를 도구로 잘 활용하는 것도 핵심 역량.

⚖️ 윤리·책임 판단

개인정보 처리, 알고리즘 편향, 보안 설계 등 기술 윤리와 법적 책임을 판단하는 능력은 인간만 가집니다.

🤝 팀·고객 소통

PM·디자이너·고객과의 커뮤니케이션, 협업·설득 능력. AI가 가장 대체하기 어려운 사람과 사람 사이의 관계.

AI 도구를 직접 써보기

기초 학습
Python + 데이터·수학 기초

NumPy, Pandas, scikit-learn 기본 사용법을 익혀두세요. AI가 어떤 데이터를 필요로 하고, 어떤 원리로 작동하는지 이해하는 것이 출발점입니다.

심화 학습
프롬프트 엔지니어링 + API 연동

OpenAI API, Anthropic API를 활용해 AI 기능을 내 프로그램에 통합해보세요. AI를 "쓰는 사람"에서 "AI를 내 서비스에 넣는 사람"으로 발전합니다.

포트폴리오
AI 활용 프로젝트 제작 · GitHub 공개

추천 시스템, AI 챗봇, 이미지 분류 앱 등 AI를 활용한 프로젝트를 만들어 GitHub에 올리세요. "AI를 활용하는 개발자"임을 증명하는 포트폴리오가 됩니다.
