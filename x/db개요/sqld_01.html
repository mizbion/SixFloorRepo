이 단원 출제 비중

기초 개념이지만 뒤 단원의 이해를 좌우합니다

데이터 모델링을 먼저 잡아야 SQLD가 편해집니다

이 단원은 현실 업무를 데이터 구조로 바꾸는 출발점입니다. 개념이 추상적으로 느껴져도, 해설을 따라가면 3층 스키마와 ERD를 한 번에 정리할 수 있게 구성했습니다.

🎯 학습목표

  1. 데이터 모델링의 목적과 흐름을 업무 관점에서 설명한다
  2. 외부·개념·내부 스키마를 3층 구조로 구분한다
  3. ERD의 엔터티, 속성, 관계, 식별자 개념을 문제 풀이에 연결한다
  4. 기출형 예상문제 15문항을 풀며 미니 강의형 해설로 재학습한다
1. 데이터 모델링이란?

데이터 모델링은 현실 세계의 업무 규칙을 데이터 구조로 정리하는 작업입니다. 그냥 그림을 그리는 게 아니라, 무엇을 저장할지, 어떤 관계로 연결할지, 어디까지 나눠 저장할지를 결정합니다.

단계질문산출물
요구사항 분석무슨 업무를 처리하나?업무 규칙, 용어 정리
개념적 모델링무슨 개체와 관계가 있나?ERD 초안
논리적 모델링테이블/키로 어떻게 바꾸나?정규화된 테이블 구조
물리적 모델링실제 DB에 어떻게 저장하나?인덱스, 저장 구조
핵심: SQLD에서는 업무 → 데이터 구조로 바꾸는 논리적 사고를 묻는 문제가 많습니다. 문법보다 관계와 기준을 먼저 잡으세요.
2. 3층 스키마

스키마는 데이터베이스를 보는 시점에 따라 나눈 논리적 구조입니다. 외부는 사용자 관점, 개념은 전체 통합 관점, 내부는 저장 관점입니다.

구분다른 이름한마디 정의예시
외부 스키마서브 스키마사용자별로 필요한 화면/뷰학생용 성적 조회 화면
개념 스키마논리 스키마DB 전체의 통합 구조학생-수강-과목 ERD
내부 스키마물리 스키마실제 저장 방식파일, 인덱스, 페이지
주의: 외부 스키마는 개인별 뷰, 개념 스키마는 전체 통합, 내부 스키마는 DBMS가 실제로 저장하는 방식입니다. 셋을 섞으면 문제를 틀리기 쉽습니다.
3. ERD 핵심 요소

ERD는 Entity-Relationship Diagram의 약자입니다. 말 그대로 엔터티(대상), 속성(특징), 관계(연결)를 그림으로 표현합니다.

요소의미시험 포인트
엔터티관리 대상사람/사물/개념을 데이터로 본 것
속성엔터티의 특징학생명, 학번, 전화번호
관계엔터티 사이 연결학생이 과목을 수강한다
식별자구별 기준기본키/후보키/대체키
암기 순서: 무엇(엔터티)을 어떤 특징(속성)으로 구분하고, 어떻게 연결(관계)되는지 본 뒤, 무엇으로 구별(식별자)할지 정합니다.
예제 데이터: 학교 수강 신청

SQLD 출제진이 좋아하는 함정 7가지

🪤 함정 1. 데이터 모델링은 ERD만 그리는 일이 아니다

모델링은 업무 규칙을 데이터 구조로 바꾸는 전체 과정입니다. 그림은 결과물일 뿐, 출발점이 아닙니다.

🪤 함정 2. 3층 스키마의 순서를 섞는다

외부 → 개념 → 내부 순서를 기본으로 기억하세요. 사용자 화면부터 실제 저장 구조까지 이어집니다.

🪤 함정 3. 개념 스키마와 내부 스키마를 혼동한다

개념 스키마는 전체 데이터의 논리 구조, 내부 스키마는 저장 방식입니다. 테이블 설계와 파일 저장을 같은 말로 보면 안 됩니다.

🪤 함정 4. 엔터티와 테이블을 같은 뜻으로만 외운다

시험에서는 엔터티를 먼저 발견하고, 그다음 테이블로 옮기는 사고가 필요합니다. 아직 물리 테이블이 아니어도 엔터티는 존재합니다.

🪤 함정 5. M:N 관계를 그대로 두려 한다

학생-과목처럼 서로 여러 개가 연결되면, 중간 엔터티(연결 엔터티)가 필요합니다. 실제 관계형 DB에서는 직접 M:N을 유지하지 않습니다.

🪤 함정 6. 식별자와 속성을 헷갈린다

학번은 학생을 구별하는 기준이고, 이름은 그냥 속성입니다. 이름이 같을 수 있지만 학번은 같으면 안 됩니다.

🪤 함정 7. 관계 방향을 이름으로만 외운다

1:N은 외우기보다 FK가 있는 쪽이 N쪽이라고 기억하세요. 시험에서 방향이 바뀌어도 원리를 알면 흔들리지 않습니다.

Q1 · 데이터 모델링의 목적
데이터 모델링의 가장 핵심적인 목적은 무엇인가?
  • ① 화면 색상을 예쁘게 정리하는 것
  • ② SQL 문법을 빠르게 외우는 것
  • ③ 현실 업무를 데이터 구조로 표현하는 것
  • ④ 서버 속도를 무조건 빠르게 만드는 것
정답 ③
현실 업무를 데이터 구조로 표현하는 것
개념 복습
모델링은 업무를 테이블처럼 바꾸는 기초 작업입니다. 어떤 데이터를 저장할지, 어떤 관계로 묶을지, 어떤 키로 구별할지를 정해야 뒤 단계가 편해집니다.
오답 정리
  • ① 디자인은 부차적입니다.
  • ② 문법 암기는 모델링의 목적이 아닙니다.
  • ④ 성능은 물리 설계와 최적화의 영역입니다.
암기 팁
모델링 = 업무를 데이터 언어로 번역하는 작업.
Q2 · 3층 스키마 순서
3층 스키마의 기본 순서로 옳은 것은?
  • ① 외부 스키마 → 개념 스키마 → 내부 스키마
  • ② 내부 스키마 → 외부 스키마 → 개념 스키마
  • ③ 개념 스키마 → 외부 스키마 → 내부 스키마
  • ④ 외부 스키마 → 내부 스키마 → 개념 스키마
정답 ①
외부 → 개념 → 내부
개념 복습
외부는 사용자가 보는 화면, 개념은 전체 통합 구조, 내부는 실제 저장 방식입니다. 사용자 관점에서 DB 핵심 구조로 들어가고, 마지막에 물리 저장으로 내려갑니다.
오답 정리
  • ②~④는 관점의 흐름이 뒤섞였습니다.
암기 팁
사람이 먼저 보고, 전체 구조를 잡고, 그다음 저장한다.
Q3 · 외부 스키마
외부 스키마에 대한 설명으로 가장 알맞은 것은?
  • ① DB 파일이 실제로 어떻게 저장되는지 보여준다
  • ② 사용자나 응용 프로그램이 보는 데이터 뷰를 뜻한다
  • ③ 전체 데이터의 통합 ERD를 뜻한다
  • ④ 인덱스 구조만을 뜻한다
정답 ②
사용자 관점의 뷰
개념 복습
외부 스키마는 사용자별로 필요한 정보만 보여주는 논리적 창입니다. 학생 화면, 교사 화면처럼 같은 DB라도 보이는 모습이 다를 수 있습니다.
오답 정리
  • ①은 내부 스키마입니다.
  • ③은 개념 스키마입니다.
  • ④는 저장 최적화에 가까운 내부 영역입니다.
암기 팁
외부 = 밖에서 보는 화면.
Q4 · 개념 스키마
개념 스키마의 특징으로 옳은 것은?
  • ① 사용자별 화면만 설명한다
  • ② 물리 파일 구조를 설명한다
  • ③ DB 전체의 통합 논리 구조를 설명한다
  • ④ SQL 문법 오류를 검사한다
정답 ③
전체 통합 논리 구조
개념 복습
개념 스키마는 여러 사용자의 요구를 모아 한 번에 보는 구조입니다. ERD를 그리는 이유도 이 개념 스키마를 명확히 하기 위해서입니다.
오답 정리
  • ① 외부 스키마
  • ② 내부 스키마
  • ④ DBMS 기능이 아닙니다
암기 팁
개념 = 전체 구조를 머릿속에 그린 설계도.
Q5 · 내부 스키마
내부 스키마에 대한 설명으로 가장 적절한 것은?
  • ① 학생별 화면 구성
  • ② 업무 규칙 문서
  • ③ ERD의 관계선 종류
  • ④ 실제 저장 파일과 인덱스 구조
정답 ④
실제 저장 파일과 인덱스 구조
개념 복습
내부 스키마는 DBMS가 데이터를 어떻게 저장할지에 대한 이야기입니다. 성능, 저장공간, 접근 속도와 연결됩니다.
오답 정리
  • ① 외부 스키마
  • ② 모델링 문서
  • ③ ERD 기호 설명입니다
암기 팁
내부 = DB 안쪽 저장 방식.
Q6 · ERD 요소
ERD의 기본 요소로 가장 알맞은 것은?
  • ① 엔터티, 속성, 관계
  • ② 트랜잭션, 커서, 인덱스
  • ③ 컴파일, 실행, 종료
  • ④ SELECT, INSERT, UPDATE
정답 ①
엔터티, 속성, 관계
개념 복습
ERD는 데이터의 대상(엔터티), 그 대상의 성질(속성), 그리고 대상끼리의 연결(관계)을 한눈에 보여주는 도구입니다.
오답 정리
  • ②는 DB 내부 기술
  • ③은 프로그램 실행 과정
  • ④는 SQL 문장 종류
암기 팁
ERD = 누가(엔터티) / 어떤 특징(속성) / 어떻게 연결(관계).
Q7 · 관계의 종류
학생 한 명이 여러 과목을 듣고, 과목 한 개도 여러 학생이 듣는다. 이 관계는?
  • ① 1:1 관계
  • ② M:N 관계
  • ③ 1:N 관계
  • ④ 독립 관계
정답 ②
다대다(M:N)
개념 복습
한쪽도 여러 개, 다른 쪽도 여러 개면 다대다 관계입니다. 관계형 DB에서는 보통 이 관계를 바로 두지 않고, 중간 엔터티를 만들어 풀어냅니다.
오답 정리
  • ① 서로 1개씩만 연결될 때
  • ③ 한쪽만 여러 개일 때
  • ④ 관계 분석이 되지 않은 상태입니다
암기 팁
둘 다 여러 개면 무조건 M:N.
Q8 · M:N 해결
학생과 과목의 M:N 관계를 논리적으로 풀기 위해 가장 적절한 것은?
  • ① 학생 테이블만 크게 만든다
  • ② 과목 테이블만 크게 만든다
  • ③ 수강 같은 연결 엔터티를 추가한다
  • ④ 관계를 삭제한다
정답 ③
연결 엔터티 추가
개념 복습
수강 테이블은 학생과 과목 사이의 관계 자체를 데이터로 만든 것입니다. 이 테이블 덕분에 수강일, 성적, 학기 같은 관계 속성도 함께 저장할 수 있습니다.
오답 정리
  • ①, ②는 구조가 깨집니다.
  • ④는 업무를 버리는 것과 같습니다.
암기 팁
M:N은 중간 테이블이 해답.
Q9 · 식별자
엔터티를 서로 구별하기 위한 기준으로 가장 알맞은 것은?
  • ① 식별자
  • ② 도메인
  • ③ 관계
  • ④ 인스턴스
정답 ①
식별자
개념 복습
식별자는 엔터티를 유일하게 구분하는 기준입니다. 학생 엔터티에서는 학번처럼 절대 중복되지 않는 값이 식별자가 됩니다.
오답 정리
  • 도메인은 허용 값의 범위
  • 관계는 연결
  • 인스턴스는 실제 행(레코드)
암기 팁
식별자 = 구별하는 이름표.
Q10 · 기본키
기본키(Primary Key)에 대한 설명으로 옳은 것은?
  • ① 중복이 가능하다
  • ② NULL만 허용한다
  • ③ 테이블마다 없어도 된다
  • ④ 각 행을 유일하게 식별한다
정답 ④
행을 유일하게 식별
개념 복습
기본키는 중복될 수 없고 NULL도 허용되지 않습니다. 데이터 모델에서 가장 중요한 식별 기준입니다.
오답 정리
  • ① 중복 금지
  • ② NULL 금지
  • ③ 일반적으로 반드시 필요
암기 팁
PK = 중복 X, NULL X, 행 구분 O.
Q11 · 후보키
후보키에 대한 설명으로 가장 알맞은 것은?
  • ① 무조건 숫자만 써야 한다
  • ② 기본키가 될 수 있는 키들의 집합이다
  • ③ 외래키만 의미한다
  • ④ 중복과 NULL을 반드시 허용한다
정답 ②
기본키가 될 수 있는 키들의 집합
개념 복습
후보키는 유일성과 최소성을 만족하는 식별 후보입니다. 이 중 하나를 골라 기본키로 정하고 나머지는 대체키가 될 수 있습니다.
오답 정리
  • ① 데이터 타입과는 무관합니다
  • ③ 외래키와 다릅니다
  • ④ 후보키는 유일해야 합니다
암기 팁
후보키 = PK 후보들.
Q12 · 속성의 예
다음 중 파생 속성(derived attribute)의 예로 가장 알맞은 것은?
  • ① 학번
  • ② 학생명
  • ③ 전화번호
  • ④ 나이(생년월일로부터 계산)
정답 ④
생년월일로 계산한 나이
개념 복습
파생 속성은 다른 속성으로부터 계산되는 값입니다. 계산 가능하므로 굳이 저장하지 않아도 되지만, 상황에 따라 저장 성능 때문에 함께 저장하기도 합니다.
오답 정리
  • ①~③은 직접 입력하는 일반 속성입니다
암기 팁
파생 속성은 계산해서 나오는 값.
Q13 · 관계의 위치
1:N 관계에서 외래키(FK)는 보통 어느 쪽에 두는가?
  • ① N쪽
  • ② 1쪽
  • ③ 양쪽 모두 필요 없다
  • ④ 무작위로 둔다
정답 ①
N쪽에 둔다
개념 복습
N쪽이 여러 번 반복되는 쪽이므로, 그 행이 어느 1쪽에 속하는지 알기 위해 FK를 둡니다. 예를 들어 학생(1)과 수강(N) 관계에서는 수강 테이블에 학번이 들어갑니다.
오답 정리
  • ② 1쪽에는 보통 PK가 있습니다
  • ③ 연결 정보가 사라집니다
  • ④ 관계가 깨집니다
암기 팁
FK는 많은 쪽(N)에 둔다.
Q14 · 모델링 순서
데이터 모델링의 흐름으로 가장 적절한 것은?
  • ① 물리적 모델링 → 개념적 모델링 → 요구사항 분석
  • ② ERD 작성 → 요구사항 분석 → 화면 설계
  • ③ 요구사항 분석 → 개념적 모델링 → 논리적 모델링 → 물리적 모델링
  • ④ 코드 작성 → 배포 → 테스트 → 요구사항 분석
정답 ③
요구사항 → 개념 → 논리 → 물리
개념 복습
업무를 먼저 이해하고, 그다음 개체와 관계를 정리한 뒤, 테이블과 키로 바꾸고, 마지막에 저장 방식까지 구체화합니다. 이 순서를 거꾸로 하면 모델이 흔들립니다.
오답 정리
  • ①, ②는 순서가 뒤집혔습니다.
  • ④는 개발 흐름입니다.
암기 팁
모델링은 업무 이해 → 구조화 → 구현 순서.
Q15 · 관계 해석 종합
아래 설명에 가장 잘 맞는 관계는? “한 학생은 여러 수강 기록을 가질 수 있고, 각 수강 기록은 한 학생에만 속한다.”
  • ① 1:1 관계
  • ② 1:N 관계
  • ③ M:N 관계
  • ④ 관계가 없다
정답 ②
1:N 관계
개념 복습
학생 1명에 수강 기록이 여러 개 붙는 구조이므로 1:N입니다. 이때 수강 테이블은 학생 쪽을 참조하는 외래키를 가집니다. 수강 기록은 같은 학생에 여러 번 등장할 수 있지만, 각 기록은 학생 하나만 가리킵니다.
오답 정리
  • ① 한 번만 연결될 때
  • ③ 양쪽이 서로 여러 개일 때
  • ④ 이미 관계를 말하고 있습니다
암기 팁
하나가 여러 개를 거느리면 1:N.
