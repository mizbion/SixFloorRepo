이 단원 출제 비중

정규화/반정규화/트랜잭션은 실전 SQL 설계의 핵심입니다

정규화/반정규화/트랜잭션, 데이터 구조의 뼈대를 잡는 단원

이 단원은 정규화, 반정규화, 트랜잭션의 정의와 실제 적용, 그리고 문제에서 자주 나오는 함정까지 미니 강의로 정리했습니다.

🎯 학습목표

  1. 정규화/반정규화의 정의와 목적을 구분한다
  2. 1~3차 정규화의 조건과 예시를 설명한다
  3. 트랜잭션의 ACID 원칙과 주요 명령을 구분한다
  4. 기출형 예상문제 15문항을 풀며 미니 강의형 해설로 재학습한다
1. 정규화(Normalization)

정규화는 데이터의 중복과 이상 현상(Anomaly)을 제거하고, 데이터 구조를 체계적으로 분해하는 과정입니다.

차수조건핵심예시
1차 정규화모든 속성 값이 원자값(더 이상 나눌 수 없음)반복/중첩 컬럼 제거전화번호1, 전화번호2 → 전화번호 테이블 분리
2차 정규화부분적 함수 종속 제거(기본키 전체에만 종속)복합키의 일부에만 종속된 속성 분리학번+과목 → 성적, 이름은 학번에만 종속
3차 정규화이행적 함수 종속 제거(키가 아닌 속성에 종속된 속성 분리)비키 속성 간 종속 제거학번 → 학과코드 → 학과명
핵심: 정규화는 중복/이상 현상을 막고, 데이터 무결성을 높입니다.
2. 반정규화(Denormalization)

반정규화는 성능 향상을 위해 일부러 중복을 허용하거나 테이블을 합치는 과정입니다. 조회 속도가 중요한 경우 사용합니다.

기법설명예시
테이블 통합자주 조인되는 테이블을 합침학생+수강 통합
중복 컬럼 추가조회 속도를 위해 컬럼 중복학생 테이블에 학과명 추가
요약 테이블집계 결과를 별도 저장월별 매출 요약 테이블
주의: 반정규화는 성능은 좋아지지만, 무결성 관리가 어려워질 수 있음을 기억하세요.
3. 트랜잭션(Transaction)

트랜잭션은 데이터베이스에서 하나의 논리적 작업 단위입니다. 여러 작업이 한 번에 성공하거나, 모두 실패해야 합니다.

특징(ACID)설명
원자성(Atomicity)모두 성공/모두 실패
일관성(Consistency)작업 전후 데이터 일관성 유지
고립성(Isolation)동시 실행 시 서로 영향 없음
지속성(Durability)커밋된 결과는 영구 보존
주요 명령: COMMIT, ROLLBACK, SAVEPOINT 등으로 트랜잭션을 제어합니다.

아래는 정규화 전후의 테이블 구조 변화 예시입니다.

정규화 전정규화 후
학생(학번, 이름, 과목1, 과목2, 점수1, 점수2)학생(학번, 이름), 수강(학번, 과목, 점수)
중복, 이상 현상 발생중복 최소화, 무결성 향상

🪤 함정 1. 정규화는 무조건 좋은 것?

정규화는 중복/이상 현상을 막지만, 성능 저하가 발생할 수 있습니다. 실무에서는 반정규화도 필요합니다.

🪤 함정 2. 1차/2차/3차 정규화 조건 혼동

1차: 원자값, 2차: 부분적 종속 제거, 3차: 이행적 종속 제거를 구분하세요.

🪤 함정 3. 반정규화는 무결성에 영향 없음?

반정규화는 성능은 좋아지지만, 무결성 관리가 어려워질 수 있음을 기억하세요.

🪤 함정 4. 트랜잭션은 부분 성공 가능?

트랜잭션은 모두 성공/모두 실패가 원칙입니다. 일부만 성공은 허용되지 않습니다.

🪤 함정 5. ACID 원칙 순서 혼동

원자성, 일관성, 고립성, 지속성(Atomicity, Consistency, Isolation, Durability) 순서와 의미를 구분하세요.

🪤 함정 6. SAVEPOINT는 취소 명령?

SAVEPOINT는 중간 저장점을 만드는 명령입니다. 취소(ROLLBACK)와는 다릅니다.

🪤 함정 7. COMMIT/ROLLBACK 혼동

COMMIT은 영구 반영, ROLLBACK은 취소입니다. 반대로 외우지 않도록 주의하세요.
