인터넷 vs 웹 — 같은 걸까?

헷갈리기 쉬운 두 개념의 차이

🤔 인터넷과 웹, 어떻게 다를까?

많은 사람들이 인터넷과 웹(World Wide Web)을 같은 말로 씁니다.
하지만 둘은 엄연히 다른 개념이에요!
📡 인터넷 (Internet)

전 세계 컴퓨터들을 연결하는 거대한 네트워크 인프라입니다.

  • 케이블, 라우터, 서버들의 물리적 연결망
  • 이메일, 웹, 파일 전송 등 모두 인터넷 위에서 동작
  • 1969년 미국 군사망 ARPANET에서 시작
🏗️ 비유: 도로망 (고속도로·국도)
🌐 웹 (Web)

인터넷 위에서 작동하는 서비스 중 하나입니다.

  • HTML 문서들이 링크로 연결된 정보 공간
  • 브라우저로 접속해서 사용
  • 1991년 팀 버너스리가 발명
🚗 비유: 도로 위를 달리는 자동차
💡
인터넷 위에서 작동하는 서비스: 웹(http), 이메일(email), 파일전송(FTP), 온라인게임 등. 웹은 그 중 하나예요!

웹의 역사

30년 만에 세상을 바꾼 기술

📅 웹 기술 핵심 타임라인

1969
1969 — ARPANET 탄생
미국 국방부가 핵전쟁에도 살아남는 통신망을 만들기 위해 개발. 최초의 인터넷 프로토타입으로, 4개 대학의 컴퓨터를 처음 연결했습니다.
1991
1991 — WWW 탄생 HTML 1.0
영국 과학자 팀 버너스리(Tim Berners-Lee)가 CERN(유럽핵물리연구소)에서 발명. "모든 사람이 정보를 쉽게 공유할 수 있어야 한다"는 생각에서 출발했어요. 오늘날 우리가 쓰는 웹의 직접적인 시작입니다.
1993
1993 — 모자이크 브라우저 등장
최초로 이미지를 텍스트와 함께 보여주는 브라우저 등장. 일반인도 웹을 쉽게 사용하게 되면서 웹이 폭발적으로 성장하기 시작했습니다.
1995
1995 — CSS & JavaScript 탄생 CSS JS
같은 해에 두 언어가 모두 등장했습니다. CSS로 웹페이지를 꾸밀 수 있게 되었고, Netscape의 개발자 브렌던 아이크가 단 10일 만에 JavaScript를 만들어 웹에 동작을 추가했습니다.
2004
2004 — Web 2.0 시대 & Gmail 등장
사용자가 직접 콘텐츠를 만들고 공유하는 참여형 웹의 시작. YouTube(2005), Facebook(2004) 등 SNS가 등장하며 웹이 단순 정보 조회를 넘어 소통의 공간이 됩니다.
2007
2007 — 아이폰 출시 → 모바일 웹 시대
스마트폰이 대중화되면서 작은 화면에서도 잘 보이는 웹이 중요해졌습니다. 이것이 나중에 배울 반응형 웹의 출발점입니다.
2014
2014 — HTML5 공식 표준 확정
동영상, 음악, 그래픽을 별도 플러그인 없이 브라우저에서 바로 재생. 지금 우리가 쓰는 HTML의 버전이 바로 HTML5입니다. <!DOCTYPE html>이 이 버전을 선언하는 코드예요.
NOW
현재 — AI가 웹을 만드는 시대
ChatGPT, Claude 같은 AI가 코드를 생성해주는 시대가 왔습니다. 하지만 기초 원리를 아는 사람이 AI를 훨씬 잘 활용할 수 있어요. 여러분이 지금 배우는 이유입니다!

서버와 클라이언트

웹의 요청-응답 구조

🍽️ 식당으로 이해하는 서버-클라이언트

웹은 항상 요청(Request)과 응답(Response)으로 작동합니다.
식당에 비유하면: 손님(클라이언트)이 주문하면 주방(서버)이 음식을 내어주는 것과 같아요.

  • Google, Naver의 컴퓨터들

URL & HTTP 이해하기

웹 주소의 구조와 통신 규약

🔗 URL 주소 해부하기

URL(Uniform Resource Locator)은 인터넷에서 특정 자원(페이지, 이미지 등)의 정확한 위치 주소입니다.
URL 구조 예시
https프로토콜
:// 
www.naver.com도메인
/ 
news/main.html경로(path)
부분설명예시
https:// 프로토콜 — 어떤 방식으로 통신할지. https는 암호화된 안전한 통신 http:// 또는 https://
www.naver.com 도메인 — 서버의 이름. 숫자로 된 IP 주소를 사람이 읽기 쉽게 변환한 것 google.com, youtube.com
/news/main.html 경로(Path) — 서버 안에서 어떤 파일인지 위치 /index.html, /about
⚠️
http://는 데이터가 암호화되지 않아 위험합니다. 현재는 https://가 표준이에요. 주소창에 🔒 자물쇠가 없으면 주의하세요!

📮 HTTP — 웹의 통신 규칙

HTTP(HyperText Transfer Protocol)는 클라이언트와 서버가 대화하는 방식의 약속입니다.
택배 규정처럼, 어떤 형식으로 요청하고 응답할지 정해놓은 규칙이에요.
📤 요청 메서드 (Method)
  • GET — 페이지 가져오기 (가장 기본)
  • POST — 데이터 전송 (로그인, 글 작성)
  • PUT — 데이터 수정
  • DELETE — 데이터 삭제
📬 응답 상태 코드 (Status Code)
  • 200 OK — 성공적으로 응답
  • 404 Not Found — 페이지가 없음
  • 403 Forbidden — 접근 권한 없음
  • 500 Server Error — 서버 오류
🔢
GitHub Pages에서 없는 페이지에 접속하면 404 오류가 뜨는 이유가 바로 이 상태 코드 때문이에요. 이제 오류 메시지가 이해될 거예요!

꼭 알아야 할 웹 용어 사전

수업에서 계속 나오는 핵심 용어들

📚 기본 용어

HTML
HyperText Markup Language
웹페이지의 구조와 내용을 만드는 언어. 태그로 요소를 정의합니다.
CSS
Cascading Style Sheets
HTML 요소의 디자인(색상, 크기, 위치)을 꾸미는 언어.
JavaScript
줄여서 JS
웹페이지에 동작을 추가하는 프로그래밍 언어. 버튼 클릭, 데이터 처리 등.
Browser
브라우저 / 웹 브라우저
웹페이지를 보여주는 프로그램. 크롬, 사파리, 엣지 등.
Server
서버
파일을 저장하고 요청이 오면 내어주는 컴퓨터. 항상 켜져 있어야 합니다.
Client
클라이언트
서비스를 요청하는 쪽. 내 컴퓨터나 스마트폰(브라우저).
URL
Uniform Resource Locator
웹 자원의 주소. https://naver.com처럼 프로토콜+도메인+경로로 구성.
HTTP/HTTPS
통신 프로토콜
클라이언트-서버 통신 규약. S가 붙으면 암호화된 안전한 통신.

📚 개발 도구 & 환경 용어

IDE
Integrated Development Environment
코드 편집기 + 디버거 등이 통합된 개발 환경. VS Code가 대표적.
Git
버전 관리 시스템
코드의 변경 이력을 저장하고 관리. 실수해도 이전 버전으로 돌아갈 수 있음.
GitHub
깃허브
Git 저장소를 인터넷에 올려두는 서비스. Pages 기능으로 무료 웹 호스팅 가능.
Hosting
호스팅 / 웹 호스팅
서버에 파일을 올려 인터넷에서 접근 가능하게 하는 서비스.
Frontend
프론트엔드
사용자가 직접 보는 화면 쪽. HTML, CSS, JS를 다룸. 우리가 배우는 영역!
Backend
백엔드
서버, 데이터베이스 등 뒷단 처리. Python, Java, Node.js 등을 사용.
DOM
Document Object Model
브라우저가 HTML을 읽어 만드는 트리 구조. JS로 이 구조를 조작해 화면을 변경.
API
Application Programming Interface
프로그램들이 서로 소통하는 창구. 날씨 앱이 기상청 API로 날씨 데이터를 가져오는 것처럼.
