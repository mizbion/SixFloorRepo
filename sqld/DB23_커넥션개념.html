백엔드 코드에서 SQL을 실행하는 것

4부의 마지막 준비 시간입니다. 파이썬 코드가 실제로 데이터베이스와 어떻게 "전화선"을 연결하는지 살펴봅니다.

STEP 1

db.query(...) 한 줄 뒤에 숨은 5단계

지난 시간 봤던 db.query("SELECT * FROM STUDENTS") 한 줄은 사실 이렇게 여러 단계로 이뤄져 있습니다. 버튼을 눌러 순서대로 확인해보세요.

conn = get_connection() # ① DB에 연결 cursor = conn.cursor() # ② 작업 도구 준비 cursor.execute("SELECT * FROM STUDENTS") # ③ SQL 실행 result = cursor.fetchall() # ④ 결과 가져오기 conn.close() # ⑤ 연결 반납
📋 단계별 설명 (한눈에 보기)
STEP 2

매번 전화를 새로 거는 건 비효율적이다

DB에 연결하는 것(①번 단계)은 마치 전화를 거는 것과 같아서, 매번 새로 연결하면 시간이 걸립니다. 그래서 서버는 미리 연결을 여러 개 뚫어두고 재사용합니다 — 이걸 커넥션 풀(Connection Pool)이라고 합니다.

🔌 미리 만들어둔 연결 5개 (커넥션 풀)
⏱️ 숫자로 비교해보면 얼마나 차이날까?

연결 하나를 새로 맺는 데 약 50ms(0.05초)가 걸리고, SQL 실행 자체는 10ms 정도 걸린다고 가정해봅시다. 요청 5개를 처리할 때 걸리는 시간을 비교해보세요.

STEP 3

SQL을 실행할 때, 값을 그대로 이어붙이면 위험하다

사용자가 입력한 값을 SQL 문자열에 그냥 이어붙이면 어떤 일이 생기는지, 직접 입력해보면서 확인해봅시다. (본격적인 공격 기법은 5부에서 더 다룹니다.)

이름 검색:
❌ 값을 그대로 이어붙인 SQL
✅ 파라미터로 전달했다면
입력값이 무엇이든, 이 방식은 항상 "이름이 정확히 그 값과 같은 사람"만 찾습니다.
STEP 4

지금까지 배운 걸 하나로 이어보면

21~23번 시간 내용을 전부 이어붙이면 이런 하나의 파이프라인이 완성됩니다. 각 단계를 클릭해서 무슨 일이 일어나는지, 어느 시간에 배운 내용인지 확인해보세요.

STEP 5

오늘의 핵심 정리

기억할 것 3가지

  • 백엔드 코드는 연결 → 커서 준비 → SQL 실행 → 결과 가져오기 → 연결 반납 순서로 데이터베이스와 대화합니다.
  • 매번 새로 연결하면 느려지므로, 실제 서버는 커넥션 풀로 미리 만들어둔 연결을 재사용합니다.
  • 사용자 입력값을 SQL에 그대로 이어붙이면 위험하며, 반드시 파라미터 바인딩으로 안전하게 전달해야 합니다.
