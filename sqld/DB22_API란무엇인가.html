API란 무엇인가

프론트엔드가 백엔드에게 정확히 어떤 규칙으로 말을 걸까요? 그 약속의 정체, API를 파헤쳐봅니다.

STEP 1

API는 식당의 "메뉴판"과 같습니다

11번 시간의 식당 비유, 기억하시나요? 손님(프론트엔드)은 주방(백엔드) 안에서 어떻게 요리하는지 몰라도, 메뉴판(API)에 적힌 대로만 주문하면 정확히 원하는 요리를 받을 수 있습니다.

메뉴(API)를 하나 클릭해서 "주문"해보세요.
STEP 2

메뉴판의 "글자 하나하나"를 읽는 법

API는 메서드(무엇을 할지) + 경로(무엇에 대해) 이렇게 두 조각의 조합으로 이루어집니다. STUDENTS라는 같은 대상을 두고, 메서드만 바꾸면 완전히 다른 동작이 됩니다. 행을 클릭해서 하나씩 확인해보세요.

💡 18번 시간에 배운 HTTP 메서드, 기억나시나요? API는 바로 그 메서드를 "이 자원(경로)에 대해" 적용하는 것입니다. 메서드는 "동사"(뭘 할지), 경로는 "명사"(무엇에 대해)라고 생각하면 쉽습니다.
STEP 3

진짜 API 문서는 이렇게 생겼습니다

실제 개발자들이 보는 API 명세서를 흉내내봤습니다. 행을 클릭해서 예시 요청/응답을 확인해보세요.

STEP 4

이 API, 실제로는 이런 코드입니다

방금 본 "학생 목록 조회" API가 파이썬(Flask)으로는 어떻게 생겼는지 봅시다. 색칠된 부분을 눌러보세요.

@app.route('/students', methods=['GET']) def get_students(): students = db.query("SELECT * FROM STUDENTS") return jsonify(students)
색칠된 코드를 클릭해보세요.
STEP 5

API 하나로 여러 곳이 함께 쓴다

같은 "학생 목록 조회 API"를 여러 클라이언트가 동시에 공유해서 씁니다. 15번 시간에 배운 뷰(VIEW)와 원리가 똑 닮았습니다 — 한 번 잘 만들어두면 여기저기서 재사용됩니다.

🔍 위 남색 상자(GET /students)를 다시 풀어보면: 메서드는 GET(STEP 2에서 배운 "조회하라"는 뜻), 경로는 /students(STEP 2에서 배운 "학생이라는 자원에 대해"라는 뜻)입니다. 즉 "학생 목록을 조회해줘"라는 요청 하나를 세 곳(웹사이트·앱·관리프로그램)이 각자 필요할 때마다 똑같이 호출합니다.
웹사이트든 앱이든 관리 프로그램이든, 모두 같은 API 하나만 호출하면 됩니다. 만약 API가 없었다면 각 프로그램마다 데이터베이스 접속 방법을 따로 알아야 했을 겁니다.
STEP 6

확인 퀴즈

API에 대한 설명으로 옳은 것은?

오늘의 핵심 정리

기억할 것 3가지

  • API는 프로그램끼리 정해진 규칙으로 대화하는 "메뉴판" 같은 창구입니다. 내부 구현을 몰라도 정해진 형식으로 요청하면 원하는 결과를 받을 수 있습니다.
  • API 하나하나는 메서드(GET·POST·PUT·DELETE = 뭘 할지) + 경로(/students = 무엇에 대해)의 조합입니다. 같은 경로라도 메서드가 다르면 완전히 다른 동작이 됩니다.
  • 응답은 대부분 JSON 형식이며(18, 20번 시간과 연결), 여러 클라이언트가 같은 API를 재사용할 수 있어서 매번 데이터베이스 연결 방법을 새로 만들 필요가 없습니다.
