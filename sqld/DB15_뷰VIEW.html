뷰(VIEW) — 쿼리를 저장해두기

2부 SQL의 진짜 마지막 시간! 매번 길게 쓰던 JOIN·서브쿼리를 이름 하나로 재사용하는 방법을 배웁니다.

STEP 1

이 JOIN 문, 오늘만 벌써 5번째 씁니다

"학생 이름 + 소속 동아리 + 방"을 조회하는 JOIN 문을 다른 화면에서도, 다른 보고서에서도 계속 다시 써야 한다면 어떨까요? 본격적으로 보기 전에, 일상에서 "뷰"와 똑같은 원리로 동작하는 것들을 먼저 찾아봅시다.

🔎 뷰(VIEW), 사실 이미 매일 쓰고 있습니다
SELECT S.NAME, C.NAME AS 동아리명, C.ROOM
FROM STUDENTS S JOIN CLUBS C ON S.CLUB_ID = C.CLUB_ID;
STEP 2

CREATE VIEW로 딱 한 번만 정의해두면?

이 JOIN 문에 이름을 붙여서 저장해두면, 다음부터는 그 이름만 부르면 됩니다.

CREATE VIEW STUDENT_CLUB_VIEW AS
SELECT S.NAME, C.NAME AS 동아리명, C.ROOM
FROM STUDENTS S JOIN CLUBS C ON S.CLUB_ID = C.CLUB_ID;
😩 뷰 없이 (매번)
SELECT S.NAME, C.NAME, C.ROOM
FROM STUDENTS S JOIN CLUBS C
ON S.CLUB_ID = C.CLUB_ID;
➡️
😌 뷰가 있으면
SELECT * FROM STUDENT_CLUB_VIEW;
한 줄로 줄었습니다! 뷰는 마치 "미리 만들어둔 테이블"처럼 SELECT할 수 있습니다.
STEP 3

뷰는 데이터를 저장하지 않는 "가상의 창문"

원본 STUDENTS 테이블의 CLUB_ID가 바뀌면, 뷰의 결과도 실시간으로 바뀝니다. 뷰 자체엔 데이터가 없기 때문입니다.

뷰는 실제로는 "SELECT 문을 기억해뒀다가, 조회할 때마다 다시 실행"하는 것뿐입니다. 그래서 원본이 바뀌면 뷰 결과도 항상 최신 상태를 보여줍니다.

뷰(VIEW)에 대한 설명으로 옳은 것은?

오늘의 핵심 정리

기억할 것 3가지

  • 뷰(VIEW)는 자주 쓰는 SELECT 문(특히 복잡한 JOIN·서브쿼리)에 이름을 붙여 저장해두는 것입니다.
  • 뷰는 실제 데이터를 따로 저장하지 않는 "가상의 테이블"입니다 — 조회할 때마다 저장된 SELECT 문이 다시 실행되어 항상 최신 데이터를 보여줍니다.
  • 뷰는 복잡한 쿼리 숨기기, 재사용성, 특정 칼럼만 노출하는 보안 등 여러 실무적 이유로 사용됩니다.
