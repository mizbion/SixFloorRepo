게시판 하나로 보는 CRUD 전체 흐름

5부 "실전 데이터 흐름 이해"의 시작입니다. 진짜 게시판 하나를 직접 조작하면서, SELECT·INSERT·UPDATE·DELETE가 실전에서 어떻게 쓰이는지 확인합니다.

STEP 1

READ 게시판 목록부터 봅시다

게시판을 열면 가장 먼저 전체 글 목록을 SELECT로 조회합니다. 이 화면 뒤에서 실제로 무슨 일이 일어나는지 먼저 확인해봅시다.

🖥️ 백엔드(Flask) 코드
@app.route('/api/posts', methods=['GET']) def get_posts(): posts = db.query( "SELECT POST_ID, TITLE, AUTHOR FROM POSTS ORDER BY POST_ID DESC" ) return jsonify(posts)
📥 화면이 열리면 브라우저가 GET /api/posts 요청을 보내고, 위 함수가 실행되어 목록 전체를 JSON으로 돌려줍니다. 실제 목록은 아래처럼 보입니다.
STEP 2

CREATE 새 글 작성하기

직접 제목과 내용을 입력하고 등록해보세요. "등록하기"를 누르는 순간 어떤 과정을 거치는지 단계별로 표시됩니다.

STEP 3

UPDATE 글 수정하기

수정할 글을 고르는 순간과, 제목을 바꿔 저장하는 순간 — 이 두 번 모두 서버와 통신이 일어납니다. 각각 어떤 SQL이 실행되는지 확인해보세요.

① 글을 고르면: 현재 내용을 먼저 불러옵니다
② "수정 저장"을 누르면: 새 내용을 서버로 보내 저장합니다
STEP 4

DELETE 글 삭제하기

삭제할 글을 고르고 삭제해보세요. "삭제하기"를 누르면 무슨 일이 일어나는지 단계별로 표시됩니다.

💡 이 버튼은 STEP 2~4에서 만든 변경사항(새 글, 수정, 삭제)을 전부 지우고, 게시판을 맨 처음 3개 글 상태로 되돌립니다.
STEP 5

확인 퀴즈

게시글을 수정하거나 삭제할 때 절대 빠뜨리면 안 되는 SQL 구문은?

오늘의 핵심 정리

기억할 것 3가지

  • 게시판 같은 실제 서비스는 결국 CRUD(Create·Read·Update·Delete) 네 가지 동작의 조합입니다.
  • 조회(목록)는 조건 없이 전체를, 상세 조회·수정·삭제는 WHERE POST_ID = ?처럼 정확히 하나의 글만 지정해서 처리합니다.
  • 이 네 동작은 각각 HTTP 메서드(GET/POST/PUT/DELETE, 18·22번)와도 그대로 대응됩니다.
